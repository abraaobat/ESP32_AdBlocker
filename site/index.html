TWO DEPLOYMENT MODES

Use it with the network you already have

Start as a DNS sinkhole, or create a separate protected Wi‑Fi subnet when your ISP router does not allow custom DNS settings.

⚙️

Mode 1 — Router DHCP

  • The router keeps DHCP and gateway duties
  • ESP32 acts as the filtered DNS server
  • Best when the router lets you set custom DNS
Internet→Router→ESP32 DNS→Devices
📶

Mode 2 — ESP32 Gateway

  • ESP32 creates a separate protected Wi‑Fi network
  • It provides DHCP, DNS and IPv4 gateway/NAPT
  • Useful when an ISP router locks DNS settings
Internet→ESP32→Protected Wi‑Fi→Devices

Important: Gateway mode uses a separate subnet behind the ESP32. Do not run two DHCP servers on the same LAN.

CLEAR EXPECTATIONS

What DNS blocking does — and does not — do

Not 100% ad blocking. DNS filtering cannot reliably block ads served from the same domain as desired content.

Encrypted DNS can bypass it. Apps using their own DoH/DoT resolvers may not use the local DNS server.

IPv6 strategy is still being developed. Current validated gateway behavior is focused on IPv4.

Not a professional firewall replacement. It is a lightweight DNS and policy gateway for appropriate home/lab scenarios.
