Roadmap / research

PORTABLE PRIVACY + FILTERING

ESP32 Travel Security Gateway for public Wi-Fi

ESP32 AdBlock Gateway is evolving beyond a DNS ad blocker into a lightweight portable gateway for hotel, café, airport, guest and travel networks. The ESP32 joins the public Wi-Fi while your phone, tablet and laptop stay on a separate private network.

Public / hotel / café Wi-Fi ↓ ESP32 AdBlock Gateway ├─ protected SoftAP ├─ DHCP + filtered DNS ├─ IPv4 NAPT └─ policy controls ↓ Phone / tablet / laptop

What the Travel Security mode is designed to do

Private subnet

Keep personal devices behind the ESP32 instead of attaching every device directly to the public hotspot.

Filtered DNS

Apply ESP32 DNS ad blocking and security-oriented domain policies instead of blindly trusting the hotspot DNS configuration.

IPv4 NAPT

Use the ESP32 as the IPv4 gateway between the protected SoftAP and the upstream Wi-Fi connection.

Stable personal SSID

Keep the same private Wi-Fi credentials for your devices while only the ESP32 changes its upstream network.

Leak controls

Research and validate controls for SMB, NetBIOS, SSDP/UPnP, mDNS and other local-service traffic toward an untrusted uplink.

Captive portal assistance

Detect likely portal state and guide the user through normal authentication without bypassing payment, credentials or terms of service.

Security boundaries

Travel Security is defense in depth, not a VPN claim. The project does not claim complete firewall, endpoint-security or VPN-equivalent protection. Without a trusted VPN, the hotspot/provider can still observe traffic patterns. Client-controlled DoH/DoT can bypass local DNS policy, and equivalent IPv6 protection must not be claimed until it is explicitly implemented and tested.

Planned Travel Security preset

Travel Security - protected private subnet: ON - IPv4 NAPT: ON - unsolicited inbound forwarding: OFF - public-hotspot DNS trust: OFF - filtered DNS: ON - local-service leak controls: ON where validated - client isolation: ON only where validated - captive-portal assistance: ON

WireGuard or another VPN tunnel is a separate research path and will only be presented as a supported feature after throughput, memory use, reconnection behavior and stability are measured on the target ESP32-S3 hardware.

FAQ

ESP32 ad blocker and public Wi-Fi questions

Can an ESP32 be used as a travel Wi-Fi gateway?

Yes, within the platform's limits. This project uses ESP32 Gateway mode: the ESP32 joins an upstream Wi-Fi network as a station and exposes its own protected SoftAP with DHCP, DNS and IPv4 NAPT.

Does it replace a VPN?

No. Network separation and DNS filtering are useful layers, but they do not provide the confidentiality of a trusted VPN tunnel.

Can it block ads and trackers?

It can block many third-party advertising and tracking domains at DNS level. DNS filtering cannot reliably block ads served from the same domain as desired content, and applications using their own encrypted DNS may bypass local DNS policy.

Will captive portals work?

Captive-portal support is planned as an assisted flow. The project will not attempt to bypass authentication, payment or access terms.

RESUMO EM PORTUGUÊS

ESP32 como gateway portátil para Wi-Fi público

O ESP32 AdBlock Gateway está sendo desenvolvido para funcionar como uma camada portátil de privacidade, isolamento IPv4 e bloqueio DNS em redes de hotel, aeroporto, cafeteria e outras redes públicas. Seus aparelhos permanecem conectados a uma rede Wi-Fi privada criada pelo ESP32, enquanto apenas o ESP32 troca de rede de acesso.

O objetivo inclui bloqueador de anúncios por DNS, filtragem de trackers e domínios maliciosos, uso de DNS configurável, NAPT IPv4, controles contra vazamento de serviços locais e assistência para portais cativos. O projeto não substitui VPN, HTTPS nem segurança do próprio dispositivo.
